# 已确认问题与对照结果

更新时间：2026-10-18。这里只保存用于后续工程工作的摘要；原始运行日志、
转储、个人配置和完整参考实现保留在本地排查目录，不进入公开仓库。

## 身份比较错误：已经复现并修正

0.2.2 将交互者描述符 `+0x0C` 的引擎单位句柄，与玩家管理器
`+0x3A8` 的当前 avatar 网络 ID 比较。二者是不同命名空间，正确的描述符
字段为 `+0x10`。历史日志示例中，单位句柄为 4196913，玩家 avatar ID 为 329，
因此主武器路径始终无法通过本机匹配。

0.2.3 使用网络 ID 比较，并分别记录 `last_actor_unit`、
`last_actor_network_id`、`last_local_network_id`。回归测试覆盖旧版误放行、
数值偶合导致的误匹配、无 avatar 标记 `0x7FFF`、增援后 ID 更新和单位复用。
这些原生指令仿真证明判定修正，不能单独证明游戏内稳定性。

## 0.2.3 两次失败：来源路径不再是必要条件

以下时间为北京时间（UTC+8），来自同一份追加日志；最终 STATUS 仅属于第二次运行。

| 运行 | 原生补丁激活 | shutdown | 激活后间隔 | 候选证据 |
| --- | --- | --- | --- | --- |
| 第一次 | 2026-10-17 16:10:05 | 16:10:32 | 27 秒 | 最后日志采样 546 次，全部类型 3 |
| 第二次 | 2026-10-17 16:15:18 | 16:16:50 | 92 秒 | 最终 STATUS 5752 次，类型 3/14/19/41/44 |

两次均为 `0.2.3-primary-only.1`；主武器候选、已启用类别候选、本机匹配和
拦截均为零。`source_observer=not_included`，五个新增项也不运行。
因此，来源观察和主武器判定/清除目标分支不是这两次失败的必要触发条件。
公共原生路径仍会对不被过滤的候选执行并修改私有计数；没有拦截不等于没安装代码补丁。

两份新小转储都是 `0xC0000005` 读访问异常，指令在 EXE+`0x626296`，
属于任务调度器；文件分别在 shutdown 之后约 6 秒、4 秒写出。它们保留的是
退出时或退出后的异常，不能自动当作最初触发点，更不能据此宣布找到了致崩函数。
用户进一步确认是普通游戏崩溃报告，没有看到错误码；没有证据将该窗口归为
反作弊报错。

## 历史隔离策略：保留加载，关闭原生补丁（后续已完成）

0.2.3 完全不拼入来源读取与历史模块，且只注册主武器开关。原生后端其余
类别/缓存代码仍有离线覆盖，但控制器仅发布掩码 0/1，不使用来源缓存。
保持分配、安装与恢复机制不变，以缩小本轮行为差异。

0.2.3 已撤回，不再推荐开启后继续尝试。下一项有判别力的对照是舰船中将
主武器关闭并应用，之后保持关闭进入任务。保存的 OFF 状态让生产入口继续
处理菜单、状态轮询及日志，但不准备或安装原生补丁。已新增整份入口的
12000 舰船帧与 20000 任务帧回归，在外部边界计数并拒绝所有原生准备/代码写入。
这是离线边界确认；实际 OFF 对照仍待用户提供。任务中保持关闭并正常活动
3–5 分钟即可，不要求重开过滤或故意死亡。

如果 OFF 仍退出，应检查无需代码写入的轮询、更新链和模组组合；如果 OFF
稳定，只能将问题进一步缩到启用原生路径，仍需逐步证明，不能直接宣布算法或
具体的原生故障机制。

完整六项源码保存在仓库最早的 `archive:` 提交中，仅供比较，不推荐安装。


## OFF 对照已完成与 0.2.4 入口修订

用户确认保留 0.2.3、关闭主武器开关后没有闪退。追加日志确认开关关闭并
应用，随后两次进入 Mission 路径均没有原生分配/激活行。其中第二次模式就绪
过渡为15:20:41Z，shutdown15:26:10Z，间隔329秒；这些时间为UTC。
最后 STATUS 来自随后一次舰船退出，不能用它代替此前任务的状态。

这使排查重点缩到开启后的原生路径，不能证明某一条指令或外部机制致崩。
旧代码存在另一个可确认的结构缺陷：从函数中段 JMP 进入压栈代码，没有
对应原函数或自有帧的 Win64 展开信息。旧指令状态测试没有覆盖这个边界。

0.2.4 改为正常 CALL/RET 与已注册展开表，先调用原生收集函数，再筛掉本机
主武器候选。实现和真实 Windows 展开验证见 NATIVE-ENTRY.md。它消除了旧架构
的缺陷，实际解决此次闪退与否仍需新包验收，不能倒推旧转储已证明了该原因。

## 0.2.5仅入口对照失败：停止这条入口路线

用户报告下潜后再次退出，运行确认为0.2.5-entry-only.1。以下为北京时间：

| 阶段 | 2026-10-18时间 / 证据 |
| --- | --- |
| 原生页分配及入口激活 | 14:17:15，VirtualAlloc2，展开表已注册 |
| 进入/返回摘要 | 14:17:18为54/54，14:17:28为354/354，14:17:33为654/654 |
| 最后成对样本 | 14:17:43，954/954 |
| shutdown | 14:17:46，激活后31秒，最终native.visits=1114次返回 |
| 转储头 | 14:17:51，0xC0000005读AV，EXE+0x626296 |

本轮生产机器码不含角色/玩家管理器、候选、保留目标读取，也不含过滤写入。
类型、身份匹配、拦截全部保持0。因此移除的筛选体不是这次退出的必要条件，
不能继续将故障归咎于“主武器没识别”或“删除主武器后损坏候选列表”。
仍共同存在代码写入/控制转移、自有原生页、调用/退出环境及其他模组组合，
当前对照不能进一步区分它们。1114次返回也不排除末尾仍有未返回的调用。

附加显示插件日志同样仅保留退出阶段的调度器读异常。shutdown比小转储早5秒，
未获得最初异常现场；普通崩溃报告、无明确反作弊错误码的用户陈述仍有效。
没有证据宣布GameGuard、显示插件或某个具体API为确定根因。
原始材料已另存本地忽略的incidents，不上传私人日志或转储。

发现诊断序列化遗漏：STATUS没有写入entry_calls/returned_calls，追加日志则
有完整成对摘要。最终返回数1114来自visits，最终进入数未知，不可报告成
1114/1114。已证明仪器实际执行，不要求用户为补这两个状态项重跑闪退。

HD2Runtime的events.md明确说明无游戏代码detour/.text写入；本项目此前选择
直接改写入口，与该运行时路线不同。这是需要修正的工程路线，并非该文能证明
反作弊触发机制。现撤回0.2.5，停止相同入口对照，加入独立于离线测试的
发布门禁；普通build/source-export拒绝打包此失败版本。原始源留作离线复现。
下一阶段先研究无游戏代码改写、满足仅本机范围的新后端，证明前不交付替代包。
