# 0.2.5 仅入口诊断

本次不是修复包；它保留 0.2.4 的 CALL 机制，以移除筛选体作为唯一研究方向。
原始函数由既有 `game.dll+0x9A35F6` 调用，返回地址仍为 `+0x9A35FB`。
对齐八字节位移更新、所有权拒绝、正常调用帧和展开表设计见
[NATIVE-ENTRY.md](NATIVE-ENTRY.md)，该文描述的0.2.4过滤结果已撤回。

当前原生源为 `native/entry_probe.S`，只包含：

1. 与0.2.4相同的三次寄存器保存及64字节调用帧。
2. 私有控制区 `+0x2244` 的进入计数。
3. 将 RCX/RDX/R8/R9、XMM 参数转交原收集函数一次。
4. 保存原 RAX 返回，递增私有 `+0x2100` 和 `+0x2248` 返回计数，再正常 RET。

除了自有栈、私有计数和自有码内地址常量，不读写游戏角色或交互数据。
原函数仍按原行为更新自己的数据。没有 Lua 从游戏工作线程执行的回调。
代码不含 classifier，不连接 player/interactable 全局地址，不读取开关掩码；
开关通过 Lua 控制安装或恢复 CALL，已进入的原生调用可安全返回保留页面。

为了保持入口机制一致，仍保留版本/签名门禁、近分配四页、RX代码页、RW控制页、
`RtlAddFunctionTable`、任务状态保护及所有权核对。注册失败不公布入口，
已公布的页与表保留至退出。Lua每约5秒写计数，关闭/退出时保存最终值。

原主武器保存ID保留为诊断开关；UI和状态明确过滤不可用。首次ON，已有OFF保留。
其余五项保存值不改。模式名 `entry_only_probe`，build_id `0.2.5-entry-only.1`。

新测试将角色和交互地址留为未映射区域，断言全部机器码数据访问只落在自有
栈、计数和常量，原函数调用一次、参数及返回正确、Win64状态保持。Windows
测试在独立进程直接执行当前生产字节并使用真实展开API。旧版筛选测试只读取
自有历史夹具，不能当成本版提供过滤效果的证据。

结果解释和实机步骤见 [ENTRY-PROBE.md](ENTRY-PROBE.md)。
