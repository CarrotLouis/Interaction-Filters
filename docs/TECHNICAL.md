# Implementation and rebuild

**Known defect / withdrawn 0.2.2:** `players+0x3A8` holds the current avatar network ID, not its unit handle. The shipped predicate incorrectly compares descriptor+0x0C (unit) against it. Descriptor+0x10 is the matching network-ID field. The original simulation conflated the two namespaces. The live 0.2.2 STATUS reports unit4196913 against network-ID329, all enabled candidates falling through the different-actor branch. Correcting that comparison was proved separately offline; the production source is preserved here as the withdrawn build until the death investigation is isolated. Statements below describing +0x3A8 as a current local unit are superseded by this correction. The death-crash trigger remains unproven: the without-mod Alt+F4 baseline produces the same task-scheduler dump fault.

The addon filters the native interactor candidate producer (`game.dll + 0x9A05B0`) before priority/distance ranking. [HD2Runtime's event reference](https://github.com/SkyeShade/HD2Runtime/blob/master/docs/events.md) describes post-event timing; the inspected Runtime/ModBuilder API does not supply this exclusion point. The loader, options menu and private native predicate are the runtime implementation.

Types come from the retained game enum. The StoryInteractableComponentData census has 57 Inspect zones; its 399 unused None zones do not enter the blacklist. Discovery, terminals, vehicle seats, sidearms and backpacks retain their native path. Every exclusion requires exactly one active local player (`[game + 0x3326468] +0x88`) and the actor descriptor's unit to equal the game's actual current local unit (`+0x3A8`). The no-avatar sentinel 0x7FFF passes. Identity is re-evaluated per candidate and respawn. A remote actor with a different unit passes regardless of its network ownership. Version 0.2.2 removes the extra fixed-blueprint and authority-bit requirements; these are recorded only to measure what the old guard would have rejected. The native consumer at 0x5BD685 pins the local count/unit fields independently of the hook.

Passing cases resume the original allowed-types gate. Exclusions use the game's original next-candidate branch; the original whitelist and subsequent ranking are untouched. If the retained target is exactly the rejected candidate, clear that local pointer so its 100 ms hold cannot restore it. A different retained target is preserved.

The predicate contains no function calls. It preserves flags, stack, non-displaced registers and floating-point state. Its only data writes are counters/diagnostic samples in private control memory and the matching local retained pointer. Installed file hashes, nine native consumer pins and the exact original patch word are required. One aligned 64-bit compare-and-exchange installs/restores the jump; ownership, page protection and instruction-cache checks prevent a torn update or overwriting another addon. Control clears before removal; published code remains allocated until process exit. The exact generated byte count and digest are recorded in filter.json.

Four private pages (16 KiB) are reserved: one RX code page and three RW control/cache pages. Control layout: u32 mask +0, u32 publication sequence +4, six u32 counters +8, u32 entry count +32; entries +64, stride16, `{entity u32, source u32, current_runtime_row u64}`. Cache capacity512. Writer validates all values and uses an odd sequence while updating. A support reader checks an even unchanged sequence, count bounds, entity and the candidate's current r13 row. Own (1), unknown, absent, stale, over-capacity or concurrently updated entries pass. This is a short-lived source cache, not a game-object write.

Diagnostics begin at control+0x2100, beyond the full cache's end at +0x2040, within the existing allocation. Sixteen u32 words hold visits, primary_seen, enabled_candidates, descriptor_missing, local_not_ready, different_actor, local_matches, legacy_rejected, last_type, last_actor_unit, last_local_unit, resource_low, resource_high, last_flags, retained_cleared and last_seen_type. A 64-type u32 histogram follows at +0x2140; an unsigned bound rejects all other indices. Updates to counts use LOCK INC. Diagnostic reads access only private memory. Samples can mix when native threads interleave; neither samples nor 32-bit wrapping counters drive behavior. Every roughly 15 seconds of active Mission operation, a compact native summary is logged; shutdown samples final counts before writing STATUS.

The 0.2.2 regressions replay the shipped 0.2.1 predicate on synthetic same-local-unit actors with a different resource/authority flag. It allows those candidates; the revised predicate blocks them while continuing to pass other unit IDs. These counterexamples establish a coverage gap, not the cause of the user's run. A second fixture executes retained native instructions from 0x9A0C74 through the original type load and into the hook: three zone indices, eight category/source cases, local/remote actors and three masks (144 executions). That checks the real zone*0x68/+0x44/register boundary rather than setting r15 to the desired answer alone. No engine call is executed by the fixture.

Allocation uses [VirtualAlloc2](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc2) with address requirements covering the complete signed rel32 window, clamped to system limits/granularity. On failure/unavailability, [VirtualQuery](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualquery) skips occupied regions and tries VirtualAlloc only in MEM_FREE regions. Access-denied/commit-exhaustion errors stop repeated attempts. Queries, backend, range, returned address and immediate Windows errors are recorded. The old +/-64 MiB blind probes are gone.

The independent origin tracker follows the user-provided Where's My Shit rule. Items seen before the first carried/podded gear are the map-start set. First-free members stay FIELD. For other identified items, local GameSession ownership can latch OWN during the first 1.5 seconds after ownership is available; that decision then freezes. Non-owned, known-source items become TEAM. Later pickup, re-drop and host transfer do not change the story. Entity+unit keys retain history through temporary absence and runtime-row relocation, and reset on world changes. A same-world session replacement preserves the story, including during host migration. Delayed goid assignment cannot erase map origin. This is an observation heuristic, not an authoritative caller-history API; late joining cannot reconstruct past transfers.

The source reader uses ReadProcessMemory, not direct game-data dereferences. Current-build Interactable manager: global 0x3326D68, cap/count +0x14038/+0x14040, entity hashmap +0x14050, descriptor pointers +0x14068, runtime rows +0x14070 stride0x370, zone count +0x340, zones stride0x68/type +0x44. Descriptor rows are 24 bytes (entity +8, unit +12, goid +16). Attachment manager global 0x3326698, hashmap +0x18, records pointer +0x38 stride0xAC; parent is a unit ID. Entity manager global 0x346BF98, unit-index hashmap +0xF22EC8, inline descriptors +0xF32F18. These factual layouts also appear in the reference. Hash multiplication uses exact 16-bit limbs, not rounded double products.

Only reference-proven Application.main_world, Network.game_session/peer_id and GameSession.in_session(session)/objects_owned_by(session, localPeer) signatures are used. All query batches save and restore Script.temp_byte_count through Script.set_temp_byte_count, including early returns and Lua errors. Missing arena/world APIs fail open; arena restoration failure permanently stops further queries. Startup grace 20 seconds; source cadence 0.25 seconds, maximum 2048 memory reads/4 MiB per snapshot, individual reads <=256 KiB, bounded component/hash counts. No per-unit World/Unit/GameObject calls. Empty support lists skip ownership queries. Timed polls over 8 ms back off and three consecutive slow polls stop source monitoring; only the support-origin filters fail open in that state. Actual in-game timing remains unmeasured.

Six rows use the [Mod Options Menu author API](https://github.com/CowboyBingus/ModOptionsMenu#for-mod-authors). Primary ID `primary_pickup_tools.primary_pickup_blocker.enabled_v2` gives the first upgrade ON without inheriting legacy `.enabled=false`; later OFF persists. Other stable suffixes: `.team_support`, `.field_support`, `.sample_bottle`, `.sample`, `.info`. Values are applied booleans; no master toggle or key polling. The resource `mods/primary_pickup_tools/primary_pickup_blocker` and GUID `8681784c-3da8-42e0-8982-3b4a2480b2d1` remain unchanged. Source tracking continues with filters OFF to preserve origins for later activation.

Rebuild on Windows with Python 3.12+, MinGW x64 and requirements-dev.txt. Clone Bingus Shared Loader and Mod Options Menu beside this project, or set PPB_BINGUS_TOOLS and PPB_MOM_SOURCE. Set PPB_TOOLCHAIN to gcc/objcopy/objdump's bin folder, and HD2_LUA51_DLL to the game's installed Lua DLL.

```powershell
python -m pip install -r requirements-dev.txt
python -B scripts/build.py --output-dir dist
```

The build recompiles the predicate, assembles/compiles the exact entry, runs both LuaJIT VMs and native emulation, packages with separate official loader tools, and reopens the archive for exact Lua-source equality. No build command deploys or starts the game. The source export excludes personal log backups, complete game dumps and the reference author's addon.


## 0.2.1 mission scope and crash investigation

The user reported crashes on the ship. Real 0.2.0 logs show successful allocation, mask1 and an installed hook there; support monitoring later said no equipment. Repeated dumps show an engine task-scheduler access violation (EXE+0x626296, source assert text `task_ids[t] == task->m_TaskID` in bikeshed.h). A separate WER dump shows an invalid task execute target. These establish a fault family, not a proved causal instruction in this addon; later dumps without a matching addon startup marker must not be attributed automatically.

The scope decoder independently implements facts from HD2Runtime's event state research. Game global 0x3326340 points to the state machine; u32 +0xAC21C is 3 Ship or 4 Mission. A Mission also requires GameMode global 0x33266A0, live count +8 exactly 1, known type +0x40 in 1..7 and readable descriptor +0x38. Its entity/unit identity scopes source history. Three additional consumer/writer pins match the retained current-build image: game+0x541409, +0xAB309C, +0xAD4C49. This uses only ReadProcessMemory; no engine API is needed to establish scope. The original eight hook pins remain separate.

Both the controller and source reader require this scope. Settings can be applied on the ship, while native allocation/installation and source engine calls remain absent. Leaving Mission disables control and restores the owned patch; returning honors saved choices. Mission identity changes invalidate cached sources. Empty support lists preserve necessary history and backpack loading signals without calling Application/Script/Network/GameSession. New source tracking remains read-only in missions, even with support switches OFF, to retain original source for later activation.

The offline regression runs the complete composed entry for 12000 ship frames with only its memory boundary substituted. Any source engine call or access to the hook site/gear data is an immediate test error. A separate real-shaped state/controller test runs 5000 ship frames and counts zero native allocations/code writes, then proves mission activation and return-to-ship restoration. This is a correction of scope and unnecessary queries, not a live-game proof that all task corruption has been eliminated.
