# 功能范围与待完成工作

目标是只过滤安装者的交互候选，防止拾回支援武器时误捡同位置的其他物品。
设置页使用 ModOptionsMenu，不注册自定义按键。

| 独立选项 | 首次默认 | 当前状态 |
| --- | --- | --- |
| 地面主要武器 | 开启 | 全部撤回，暂无可用过滤版 |
| 队友召唤的支援武器 | 关闭 | 隔离版暂不提供 |
| 野生/地图支援武器 | 关闭 | 隔离版暂不提供 |
| 掉落样本瓶 | 关闭 | 隔离版暂不提供 |
| 松散样本 | 关闭 | 隔离版暂不提供 |
| 场景信息交互，如售货机、工具、叉车 | 关闭 | 隔离版暂不提供 |

来源规则沿用用户确认的原始召唤来源：队友召唤的支援武器即使被本人拿起后
再丢下，仍算队友武器；本人召唤的支援武器始终应允许捡回。参考附件说明
形成的观察规则和完整实现保留在历史中，恢复时必须重新审查时机和稳定性。
来源不确定时允许拾取，不应误拦本人武器。

后续顺序：

1. 已确认退出提示为普通游戏崩溃报告，没有看到错误码。
2. OFF 对照已完成且未闪退；0.2.4 开启仍闪退，已撤回。0.2.5仅入口对照执行后也退出，已撤回；不再重复同一入口测试。
3. 缓存研究已复现旧版保留目标的结构错误，并证明正常帧的Lua/角色/候选顺序及
   模拟中只改本机目标可改变请求。下一步验证空间记录寿命、额外世界更新路径、
   本机身份与增援复用；详见[CACHE-BACKEND-RESEARCH](CACHE-BACKEND-RESEARCH.md)。
   现有正向允许列表不能直接当作完整排除列表，所有自动交互路径也需单独核实。
4. 在稳定基础上逐项恢复其他独立选项和来源功能，各自验证默认值、保存、
   来源分类、死亡/增援与房主/客机边界。
5. 完成对应实机验收后再发布完整六项版本。

旧设置保留，恢复可选项时应使用原有持久化 ID，不迁移 GUID 或建立第二份模组。
